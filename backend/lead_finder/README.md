# Поиск потенциальных клиентов для «Лакония Клин» (Уфа)

Первый MVP: ищет открытые веб-публикации, которые могут быть заявками на уборку, отбрасывает очевидные вакансии и рекламные объявления исполнителей, убирает дубли и сохраняет отчёт в JSON. По желанию отправляет сводку в Telegram владельца. Клиентам агент не пишет.

## Запуск

Требуется Python 3.11+; модуль использует стандартную библиотеку Python, дополнительные пакеты не нужны.

```bash
cd backend
python -m lead_finder.agent --limit 5
```

Результат по умолчанию сохраняется в `backend/lead-finder-results.json`, история ссылок — в `backend/.lead-finder-seen.json`. Эти файлы локальные и не должны коммититься.

Firecrawl Search API документирован здесь: https://docs.firecrawl.dev/features/search. API позволяет начать без ключа с ограничениями; для более высоких лимитов задайте переменную окружения `FIRECRAWL_API_KEY`. Ключ не помещайте в исходный код.

## Telegram владельца (не клиентам)

Создайте бота и получите ID собственного чата, затем задайте секреты в окружении:

```bash
export TELEGRAM_BOT_TOKEN="..."
export TELEGRAM_CHAT_ID="..."
python -m lead_finder.agent --limit 5 --telegram
```

Флаг `--telegram` обязателен для отправки отчёта. Без него программа только печатает и сохраняет результаты.

## Как оцениваются публикации

Сначала применяются прозрачные русскоязычные правила: признаки заказа уборки повышают оценку, слова о вакансии/резюме отбрасывают публикацию, наличие упоминания Уфы повышает оценку. Это не гарантия, что автор реально купит услугу. Перед контактом проверяйте исходную публикацию и её дату вручную.

## Ограничения первой версии

- Результаты зависят от индекса поискового провайдера и его лимитов.
- Некоторые страницы могут быть закрыты, устареть или описывать не клиента.
- Дата публикации может отсутствовать в поисковом фрагменте.
- Не обходятся CAPTCHA, логины, ограничения доступа или закрытые группы.
- Нет автоматических сообщений клиентам, сбора личных телефонов или автоматической записи в CRM.
