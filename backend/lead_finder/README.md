# Поиск потенциальных клиентов для «Лакония Клин» (Уфа)

Агент ищет через Firecrawl Search API **публично индексируемые** страницы, где люди в Уфе просят уборку, и формирует JSON-отчёт с тремя списками: **«Подтверждённый кандидат»**, **«Требует проверки»** и **«Отклонён»**. Каждый день (после настройки ниже) он присылает владельцу в Telegram только **новые** находки.

Агент только читает. Он не пишет клиентам, не публикует комментарии, не собирает личные телефоны, не обходит логины, CAPTCHA и блокировки.

## Что приходит владельцу в Telegram

Если после проверки «виденных раньше» ссылок остались новые «Подтверждённые» или «Требует проверки» кандидаты, приходит одно сообщение:

- до 15 новых подтверждённых и до 10 новых на проверку (остальное указано строкой «…и ещё N» и есть в JSON-отчёте);
- у каждого: заголовок, источник, дата, оценка, фрагмент до 300 символов и ссылка;
- отклонённые кандидаты никогда не отправляются;
- ссылки, которые уже были в предыдущих сводках, не повторяются;
- если новых нет, Telegram молчит.

Порядок работы: поиск → пометка `previously_seen` по сохранённому списку ссылок → сводка только из новых → отправка → только после успешной отправки список ссылок обновляется. Если Telegram недоступен, запуск завершается ошибкой, а те же кандидаты придут в следующий раз.

Если **ни один** поисковый запрос не выполнился (неверный ключ, лимит, сбой), запуск завершается ошибкой (код 4) и это видно в Actions: агент не изображает «заявок нет».

## Даты и «Подтверждённый кандидат»

- Подтверждённым кандидат становится только если **источник сам передал дату публикации** (`date_source: "api"`), запрос явный, указана Уфа, оценка от 80 и публикация не старше 90 дней.
- Если API дату не прислал, агент пытается найти её во фрагменте: «сегодня», «вчера», «позавчера», «N дней/недель/месяцев назад», «час/минуту назад», «20 октября», «20.10.2026» (учитывается первое упоминание; даты в будущем игнорируются; день и месяц без года, которые ещё впереди, считаются прошлым годом). Такой кандидат помечается `date_source: "snippet"`, в сводке стоит «(по фрагменту)», и он **максимум «Требует проверки»**, никогда не «Подтверждённый». Если по фрагменту публикация старше 90 дней, кандидат отклоняется.
- Нет даты вообще (`date_source: "none"`): «Требует проверки».

## Запуск вручную

Нужен Python 3.11+, агент использует только стандартную библиотеку.

```bash
cd backend
python -m lead_finder.agent --limit 5            # отчёт в lead-finder-results.json
python -m lead_finder.agent --limit 5 --telegram # то же + сводка владельцу (нужны TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID)
```

Отчёт сохраняется в `lead-finder-results.json`, список просмотренных ссылок в `.lead-finder-seen.json`. Оба файла локальные и не должны коммититься (они в `.gitignore`).

Коды выхода: `0` успех, `3` не удалось отправить Telegram, `4` ни один поисковый запрос не выполнился.

## GitHub Actions

Workflow **Find Ufa cleaning leads** (`.github/workflows/lead-finder.yml`) состоит из двух job:

1. **test** запускает `pytest tests/test_lead_finder.py`. Это единственное, что выполняется на pull request. Реальный поиск на PR **не запускается**.
2. **search** (после успешного test) запускается каждый день в 04:00 UTC (**09:00 по Уфе**) и вручную (Actions → Find Ufa cleaning leads → Run workflow, лимит 3, 5 или 8 результатов на запрос). Список просмотренных ссылок хранится между запусками в кэше Actions (`actions/cache`, ключ с `run_id`), JSON-отчёт прикладывается как артефакт на 7 дней.

**Важно про расписание.** GitHub запускает `schedule` только для workflow, который лежит в основной ветке (`main`). Пока PR не влит, по расписанию ничего не работает, а вручную запустить search можно после слияния. Кроме того, GitHub отключает расписание в репозитории без активности 60 дней: если запуски вдруг прекратились, включите workflow заново во вкладке Actions. Кэш хранится, пока им пользуются хотя бы раз в 7 дней; если его сбросили, при следующем запуске в Telegram придёт всё найденное заново один раз.

## Как добавить секреты

GitHub → репозиторий → **Settings → Secrets and variables → Actions → New repository secret**. Значения никогда не выводятся в логах и не хранятся в коде.

| Секрет | Зачем | Обязателен |
|---|---|---|
| `FIRECRAWL_API_KEY` | ключ Firecrawl Search API (https://docs.firecrawl.dev/features/search); без него лимиты жёсткие и запросы могут отклоняться | рекомендуется |
| `LEAD_TELEGRAM_BOT_TOKEN` | токен бота, который пришлёт сводку (удобнее отдельный бот от @BotFather) | для Telegram |
| `LEAD_TELEGRAM_CHAT_ID` | числовой id чата владельца: сначала напишите боту `/start`, затем узнайте id (например, через @userinfobot) | для Telegram |

Флаг `--telegram` workflow добавляет только если заданы **оба** секрета Telegram. Если их нет, поиск работает, отчёт доступен как артефакт, а сводка не отправляется (при этом найденные ссылки считаются просмотренными).

## Почему результатов может быть мало

Это нормально и честно, а не ошибка:

- Агент видит только то, что поисковый индекс уже собрал. Закрытые группы, чаты и страницы за логином он не видит, а Avito, VK и Telegram часто не отдают дату и полный текст.
- Многие люди ищут уборку в закрытых чатах и рекомендациях, а не в публичных постах.
- Страницы клининговых компаний, каталоги, отзывы, вакансии и рекламу агент отклоняет, и это большая часть выдачи.
- Без даты от источника кандидат не бывает «Подтверждённым», поэтому часть находок приходит как «Требует проверки». Открывайте ссылку и проверяйте актуальность вручную до любых действий.
- Нулевое число кандидатов допустимо и лучше ложных заявок. Счётчик «запросы API успешны» означает только, что поисковый API ответил без ошибки, а не что страницы-источники открывались напрямую.

## Тесты

```bash
cd backend
python -m pytest -q tests/test_lead_finder.py
```

Тесты не зависят от фиксированных дат (всё считается от текущей даты) и проверяют классификацию, разбор дат во фрагментах, запрет «Подтверждённого» без даты от источника, дедупликацию по ранее виденным ссылкам, сводку (лимиты, отсутствие повторов, отклонённые не отправляются), порядок «пометить → сводка → отправить → сохранить», безопасность токена в ошибках и защитные условия workflow.

## Ограничения и безопасность

Агент использует только результаты публичного веб-поиска. Он не обходит логины, CAPTCHA, HTTP 403 или другие ограничения доступа, не обращается к закрытым группам и не использует неофициальные API. Страницы напрямую не открываются: недоступность источника фиксируется в сводке, а поиск продолжается по остальным запросам.
