# Telegram-боты «Лакония Клин» — план реализации

## Цель
Создать два отдельных Telegram-бота с общей серверной частью и базой данных.

1. **Клиентский бот** — принимает запросы на уборку, отвечает на частые вопросы и собирает данные с согласия клиента.
2. **Закрытый бот владельца** — показывает заявки, меняет статусы и расписание, запрашивает подтверждение важных действий и показывает отчёты.

## Ограничения и безопасность
- Текущий сайт на GitHub Pages — статический. Токены Telegram и другие секреты нельзя размещать в HTML/JavaScript сайта или в репозитории.
- GitHub используется для кода; ботам нужна отдельная серверная часть и постоянное хранилище.
- Хранить минимум необходимых данных: имя, телефон, район/адрес оказания услуги, тип уборки, желаемая дата, статус, согласие и время его получения.
- До выбора базы и хостинга проверить применимые требования к персональным данным РФ, включая локализацию. Не отправлять данные клиентов в зарубежные сервисы без проверки правового основания.
- Закрытый бот должен проверять Telegram user ID на сервере для каждой команды. Одного знания ссылки на бота недостаточно.
- Не выполнять автоматические массовые рассылки и холодные звонки. Маркетинговые действия — только при надлежащем согласии.
- ИИ может готовить ответы и рекомендации; скидки, окончательная цена, подтверждение заказа, отмена и другие обязательства перед клиентом требуют подтверждения владельца на первом этапе.
- Не включать реальные токены, пароли, персональные данные и ключи API в Git.

## Первая версия (MVP)

### Клиентский бот
- Команда /start и краткое описание услуг.
- Кнопка «Оставить заявку».
- Последовательный сбор типа уборки, площади, района/адреса, желаемой даты, имени и телефона.
- Отдельное явное согласие на обработку персональных данных с доступной ссылкой на политику.
- Подтверждение отправки и идентификатор заявки.
- Передача заявки в общий сервер; защита от повторной отправки.

### Бот владельца
- Проверка Telegram user ID по серверному списку разрешённых пользователей.
- Уведомление о новой заявке.
- Карточка заявки и кнопки статусов: «Новая», «Связаться», «Подтверждена», «Выполнена», «Отменена».
- Просмотр заявок и расписания.
- Журнал изменений: кто, что и когда изменил.
- Подтверждение перед действиями, влияющими на клиента.

### Сервер и данные
- API с проверкой входных данных и ограничением частоты запросов.
- Общая база данных с разграничением доступа.
- Переменные окружения или секрет-хранилище для токенов и ключей.
- Резервное копирование, журнал ошибок и тесты.
- Разделение тестовой и рабочей среды.

## Последовательность работ
1. Выбрать хостинг и базу данных с учётом требований к данным клиентов в РФ.
2. Создать ботов через официального BotFather и безопасно сохранить токены вне репозитория.
3. Реализовать сервер/API и схему заявок.
4. Подключить клиентского бота.
5. Подключить закрытого бота владельца и проверку Telegram ID.
6. Добавить тесты на права доступа, валидацию, дубли и статусы.
7. Провести тестирование без реальных клиентских данных, затем пилот.
8. Подключить форму сайта после отдельной проверки и выбора подходящего размещения сайта для коммерческого проекта.

## Бюджет и автономность
Ориентир после тестового запуска — до 3 000 ₽ в месяц. Перед выбором провайдера проверить актуальные тарифы; расходы на хостинг, сообщения и ИИ не считать бесплатными без подтверждения. Рутинные действия можно автоматизировать, но важные решения на первом этапе подтверждает владелец.

## Текущий статус
Это план, а не готовая работающая интеграция. Боты, сервер, база данных и токены ещё не настроены. Работа ведётся в отдельной ветке feat/telegram-bots-foundation; основная ветка main не изменяется.
